## 2. Backend Controller Inventory

All 12 controllers live in `AitoWorkflowAndHuddleGenerator.Api\Controllers\`. All are
`[ApiController]`, all require `[Authorize(Policy = Policies.AccessAsUser)]` (the
`access_as_user` delegated scope), and all dispatch through MediatR (`ISender.Send(...)`) to
an Application-layer Command/Query handler — no controller contains direct business logic or
direct data access.

| # | Controller | Route prefix | Purpose |
|---|---|---|---|
| 1 | `ActivitiesController` | `api/activities` | Workflow activity catalog (list, by id, by role) |
| 2 | `AiToolsController` | `api/ai-tools` | AI tool catalog |
| 3 | `CurrentUserController` | `api/auth` | Authenticated user identity/profile |
| 4 | `HuddleCoachingController` | `api/huddle-coaching` | Coach directory, availability, booking |
| 5 | `HuddleLaunchPlansController` | `api/huddle-launch-plans` | Frontier Accelerator launch plan + email draft |
| 6 | `HuddlePlansController` | `api/huddle-plans` | Per-role persistent Huddle learning plan |
| 7 | `HuddlesController` | `api/huddles` | Huddle catalog, detail, recommended path, votes |
| 8 | `HuddleSessionsController` | *(no class-level route — see note)* | Huddle session progress/completion |
| 9 | `RolesController` | `api/roles` | Application role catalog |
| 10 | `WorkflowBucketsController` | `api/workflow-buckets` | Workflow bucket definitions |
| 11 | `WorkflowCalendarController` | `api/workflows/calendar` | Adds generated workflow activities to Outlook calendar |
| 12 | `WorkflowsController` | `api/workflows` | Saved/favorited user workflows (CRUD) |

**Note on `HuddleSessionsController`**: unlike the other 11 controllers, it has no
class-level `[Route]` attribute. Each action instead carries its full route on the
`[HttpGet]`/`[HttpPut]`/`[HttpPost]` attribute itself (e.g. `[HttpGet("api/huddles/{externalId}/session")]`,
`[HttpGet("api/huddle-sessions/me/incomplete")]`), so its endpoints are split across the
`api/huddles/...` and `api/huddle-sessions/...` path spaces rather than owning one prefix.
Confirmed from source; not an inferred pattern.

**Minor inconsistency (not fixed — read-only analysis)**: `WorkflowCalendarController` uses
the literal string `"AccessAsUser"` on its `[Authorize(Policy = "AccessAsUser")]` attribute
instead of the `Policies.AccessAsUser` constant every other controller uses. Functionally
equivalent today (the constant's value is `"AccessAsUser"`), but it means this one
authorization check would silently stop matching if the constant's value were ever renamed.

## 4. Backend Functionality Mapping

Every endpoint dispatches a MediatR `Command` (write) or `Query` (read) to a co-located
handler under `AitoWorkflowAndHuddleGenerator.Application\Features\...`, confirmed present via
full directory listing of the `Features` tree. Grouped by domain:

- **Activities** — catalog read, read-by-id, read-by-role. Read-only.
- **AiTools** — catalog read. Read-only.
- **Identity** — `GetCurrentUserQuery` → `ICurrentUserService` → current user's claims-derived
  identity/profile.
- **Roles** — catalog read, optionally scoped by `module` (Huddle vs Workflow — see the
  `getRoles.ts` comment in Section 5 explaining why the Workflow Builder frontend passes
  `module=Workflow`).
- **WorkflowBuckets** — catalog read.
- **Workflows** (saved workflows) — full CRUD plus a dedicated favorites read and a `PATCH`
  for toggling favorite state, all using optimistic concurrency (`RowVersion` on
  update/toggle).
- **Workflows.Calendar** — `AddWorkflowCalendarEventsCommand` → `IWorkflowCalendarService` →
  Microsoft Graph (see Section 8).
- **Huddles.Catalog** — catalog read (with filters), single-huddle detail read (optionally
  scoped to one role's placement), recommended 7-week path read.
- **Huddles.Votes** — get/set/remove a user's vote on a Huddle topic.
- **Huddles.Sessions** — get/save a user's session, set per-activity completion, mark session
  complete, list incomplete/resumable sessions. All use `RowVersion` optimistic concurrency.
- **Huddles.Plans** — get/save/reset a user's persistent per-role Huddle learning plan.
- **Huddles.LaunchPlans** — get/save/reset the Frontier Accelerator launch plan, plus create a
  Graph email draft (`IHuddleLaunchMailService`).
- **Huddles.Coaching** — list coaches, get a coach's availability (via
  `ICoachSchedulingService` → Microsoft Graph `getSchedule`), book a coaching session (via
  Graph `me/events`).

## 6. Frontend → Backend Mapping

Every one of the 34 frontend calls in Section 5 was matched to a specific backend endpoint
from Section 3 by comparing HTTP method and path template; all 34 matched exactly one
backend endpoint. No frontend call was found that targets a path with no corresponding
backend route.

**Backend endpoints with no matching frontend call found in the files read in this pass:**
- `GET /api/activities/by-role/{roleExternalId}` (`ActivitiesController.GetActivitiesByRole`)
  — no `by-role` call found in `workflow-builder/api/` or `huddle/api/`.
- `GET /api/workflows/favorites` (`WorkflowsController.GetFavorites`) — no `favorites`-path
  call found in `saved-workflows/api/`; `getMyWorkflows` supports an `isFavorite` query filter

These two are reported as "not found in the frontend `api/` layer files read"; they may still
be invoked from a component/hook not covered by this pass (only `api/`, `auth/`, and the
top-level `api/` core files were read — `hooks/*.ts`, `components/*.tsx`, and `pages/*.tsx`
were not individually opened). **Requires code-review or environment confirmation** if the
Threat Model needs a definitive dead-endpoint determination.

## 7. Swagger / OpenAPI Information

Confirmed from `AitoWorkflowAndHuddleGenerator.Api\Extensions\SwaggerExtensions.cs`:

- The OpenAPI JSON document is generated using the built-in ASP.NET Core 9
  `Microsoft.AspNetCore.OpenApi` package (`services.AddOpenApi(...)` / `app.MapOpenApi()`),
  **not** Swashbuckle for document generation.
- A document transformer adds a single `Bearer` (HTTP, scheme `bearer`, format `JWT`) security
  scheme and a global security requirement, so every operation in the generated spec is marked
  as requiring a bearer token.
- `app.MapOpenApi()` is called **unconditionally, in every environment** — an in-code comment
  explicitly states this is so the JSON document "can be scanned by the URSA Web Scanner" and
  must not depend on how an environment happens to be named.
- `Swashbuckle.AspNetCore.SwaggerUI` supplies only the interactive browsing UI, and that UI is
  gated to `app.Environment.IsDevelopment()`, mounted at route prefix `swagger`, pointing at
  `/openapi/v1.json`.
- `Properties\launchSettings.json` confirms the Development profile launches directly to
  `swagger` on `https://localhost:7001` / `http://localhost:5001`.

**Hosted QA/UAT Swagger URL cannot be determined from static repository analysis and must be
obtained from the deployed environment/App Service configuration.**

No appsettings file, launch profile, or CORS configuration in the repository names a QA, UAT,
or Production hostname; `appsettings.json`'s `Cors:AllowedOrigins` array is empty (populated
at deploy time from outside the repository), and `AzureAd:TenantId`/`ClientId`/`Audiences`
are likewise empty placeholders in source control.

## 8. Microsoft Graph API Mapping

Three Infrastructure-layer services make outbound Microsoft Graph calls, all via
delegated-user tokens obtained through `Microsoft.Identity.Web`'s `ITokenAcquisition
.GetAccessTokenForUserAsync([scopes])` (confirmed in Section-2/3 backend reading and the
WI-12 migration — this outbound path was explicitly preserved unchanged by that migration).
All three use hand-rolled `HttpClient` calls to `https://graph.microsoft.com/v1.0/` (never
`GraphServiceClient` or `IDownstreamApi`), and all three `HttpClient` registrations in
`Infrastructure\DependencyInjection.cs` are wrapped with
`GraphAntiSsrfPolicyFactory.CreateHandler` (WI-02 AntiSSRF protection) via
`ConfigurePrimaryHttpMessageHandler`.

| Service | Graph call | Scope requested | Purpose |
|---|---|---|---|
| `GraphWorkflowCalendarService` | `POST me/events` | `Calendars.ReadWrite` | Adds workflow activities to the user's Outlook calendar |
| `GraphCoachSchedulingService` | `POST me/calendar/getSchedule` | (from `CoachSchedulingOptions.GraphScopes`, configuration-driven) | Reads free/busy for the user + coach to compute mutually available slots |
| `GraphCoachSchedulingService` | `POST me/events` | (same as above) | Books a Teams meeting with the coach (`isOnlineMeeting: true`, `onlineMeetingProvider: teamsForBusiness`) |
| `GraphHuddleLaunchMailService` | `POST me/messages` | `Mail.ReadWrite` | Creates a **draft** (never sent automatically) branded launch email in the user's mailbox, with an inline banner image attachment |

**Total Microsoft Graph operations found: 4 call-sites across 3 distinct Graph endpoints**
(`me/events` is called from two different services for two different purposes).

All three services convert Graph HTTP failures into a domain
`ExternalServiceUnavailableException` rather than propagating raw Graph error responses to
the frontend.

## 11. Threat Model API Details (per-connector)

**Connector: Frontend ↔ Backend REST API**
- Protocol/auth: HTTPS, `Authorization: Bearer <Entra access token>` on every request (attached
  in `apiClient.ts`); validated inbound by MISE v2.0 against the `AccessAsUser` policy
  (`access_as_user` delegated scope) on every controller.
- Data crossing the boundary: workflow/activity/role/AI-tool catalog data; user-owned saved
  workflows; Huddle catalog, session progress, votes, learning plans, launch plans; coach
  directory, availability windows, and booking requests (which include the coaching question
  text as an unstructured field, forwarded into the Graph event body — see Section 8).
- CORS: explicit allow-list (`Cors:AllowedOrigins`), enforced before authentication in the
  pipeline; empty in source, populated per environment at deploy time.

**Connector: Microsoft Entra ID (inbound)**
- MISE v2.0 (`Microsoft.Identity.ServiceEssentials.AspNetCore` — added in WI-12) validates the
  inbound bearer JWT against `AzureAd:Audiences`, `AzureAd:TenantId`, and the
  `AzureAd:Protocols:Bearer:TokenTypes:AccessToken` settings. `AzureAd:Instance` is
  `https://login.microsoftonline.com/`.

**Connector: Microsoft Entra ID (outbound, for Graph)**
- `Microsoft.Identity.Web`'s `AddTokenAcquisition()` + `AddInMemoryTokenCaches()` provide
  `ITokenAcquisition.GetAccessTokenForUserAsync([scopes])`, used by all three Graph services
  (Section 8) to mint a delegated user token on demand. Tokens are cached in memory only (no
  distributed/persistent token cache configured in source).

**Connector: Microsoft Graph**
- See Section 8 for the exact calls, scopes, and AntiSSRF wrapping.

**Connector: SQL Server**
- EF Core 9 (`Microsoft.EntityFrameworkCore.SqlServer`), split-query behavior enabled for
  Huddle catalog/role-path reads, an `AuditableEntityInterceptor` for audit fields, migrations
  assembly = the Infrastructure project itself. No raw SQL / `FromSqlRaw` usage was found in
  any file read.
