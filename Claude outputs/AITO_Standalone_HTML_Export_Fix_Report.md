# AITO Standalone — Huddle HTML Export: Structural/Visual Alignment Report

**Scope:** Modify Standalone's Huddle HTML export so its generated output matches the manager's mock as closely as possible, using Standalone's own existing data-fetching and presentation-model logic. No manager data-fetching logic was copied, no manager/mock data was hardcoded, and no unrelated functionality, schema, or backend code was touched.

**File changed:** `AITO Workflow and Huddle Generator In App/frontend/aito-workflow-and-huddle-generator-frontend/src/features/huddle/exports/html/exportHuddleHtml.ts` — the only file modified. Confirmed via a full mtime scan of `src/**/*.ts(x)` that no other file in Standalone changed, and `C:\AITO-Recovered` was not touched (no commands were run against it in this task).

## 1. Investigation method

Three inputs were compared before any change was made:

- **Ours (current):** the uploaded HTML export generated by Standalone's pre-fix code, dated 2026-09-23, for placement `AE-PLAN` ("Prioritize Accounts and Build an Actionable Account Plan," AE role).
- **Manager's mock:** the uploaded HTML export dated 2026-09-18, same placement/role.
- **"Manager's implementation" file:** on inspection this turned out to be an older snapshot of Standalone's *own* `exportHuddleHtml.ts` (diffed at ~590 shared lines against the current file), not a separate codebase — useful as a record of what this exporter's logic looked like before some recent changes, not a foreign reference.

Both HTML outputs were stripped of base64 image data and reformatted one-tag-per-line, then diffed. The resulting diff was read in full and every difference was classified as one of:
- **(a) a real regression** — code that no longer does what the data supports;
- **(b) a legitimate data difference** between the Sept 18 and Sept 23 snapshots of Standalone's own data, requiring no code change; or
- **(c) an intentional improvement** already in the current code (confirmed by in-file comments recording prior manager direction) that should not be reverted.

## 2. Findings

### (a) Regressions fixed

**"Why This Matters" card was showing static, repeated content instead of per-activity data.**
`activityCard()` rendered a fixed `.activity-discuss-card` ("Discuss while practicing") using the Preparation panel's `keyTalkingPoints`, identical on every activity card. A comment in the code claimed *"that field [WIIFM] does not exist on this app's activity model."* That claim is no longer true: `activity.whyThisMatters` is a first-class field on `HuddlePresentationActivity` (`types/huddlePresentation.types.ts`), populated by `createHuddlePresentationModel.ts` directly from the API response, which in turn is populated in `static-api-data.json` from `HuddleActivities.WhyThisMatters` — the data pipeline this session corrected in an earlier task. Checked directly against the live data: **all 506 activities** across `placementDetails` have a populated `whyThisMatters` value.

The mock renders this as `<section class="activity-detail-card activity-wiifm-card"><h3>Why This Matters</h3><p>…</p></section>` — and the CSS for `.activity-wiifm-card` already existed, unused, in the current stylesheet. Fixed by rendering that card from `activity.whyThisMatters` instead, and removing the now-dead `discussionWhilePracticing` parameter and the stale `.activity-discuss-card` CSS rule/comment.

**"Context Required" was wrapped in a one-item bullet list instead of a paragraph.**
`questionList([activity.requiredContext], "")` wrapped this single string value in `<ul class="question-list"><li>…</li></ul>`. The mock (and the field's own nature — one string, not a list) uses a plain `<p>`. Fixed to render `<p>{activity.requiredContext}</p>` directly.

**Resource cards never showed a "Top 5 agent" badge, even though the export already computes exactly that.**
`createHuddleHtmlExport()` already builds `topFiveUsedAgents` — the subset of this Huddle's agents matching the five names Frontier Accelerator promotes org-wide (`TOP_FIVE_AGENT_NAMES`), matched via the same `agentArtwork` lookup already used for the Overview panel's "Top 5 agents" band. But `resourceHubToolCard()` rendered only an empty `<div class="resource-tool-badge-slot"></div>`, with a comment claiming *"This app has no agent-governance/Top-5 data source to populate it from."* That's also no longer accurate — the membership test already exists two functions away in the same file. Fixed by passing an `isTopFive` flag (computed via the existing `topFiveUsedAgents` array, no new data source) into `resourceHubToolCard()`, which now adds the `top-five-resource` class and a `<div class="resource-tool-badge">Top 5 agent</div>` badge — reusing CSS (`.top-five-resource`, `.resource-tool-badge`) that was already defined but orphaned.

### (b) Confirmed legitimate data differences — not changed

- **Agent card text placement** (e.g. Sales Agent's short subtitle vs. its "What it is" detail): checked directly against `static-api-data.json` — `ShortDescription` currently holds the long descriptive text and `WhatItIs` currently holds "Orchestrator" for this agent. The mock's Sept 18 snapshot had these two fields swapped. The rendering code treats both fields identically in both versions; only the underlying field *values* differ between snapshots. No code change.
- **Missing "Open agent" links** (Sales Agent, ECIF Agent, Microsoft 365 Copilot in the Resources panel): the code correctly gates the link on `agent.showAccessLink`. Checked directly against the live data: `showAccessLink` is `false` for these agents in the current dataset, even though `accessUrl` is populated. This is a data-layer value, not an export-code bug, and fixing it would mean touching the data build (out of this task's file scope: only the HTML export file was to be changed). **Flagged here for visibility, not fixed.**
- **"ECIF Agent, surfaced through Sales Agent" shown as one combined label**, vs. the mock's plain "ECIF Agent" name plus a separate "Surfaced through Top 5 Agent" badge: our current data's `displayLabel` already encodes the relationship as text. Reproducing the mock's separate-badge treatment would require inventing a new "surfaced through" relationship field that doesn't exist in Standalone's data model today — that's new data plumbing, not a presentation fix, so it was left alone.
- Various WIIFM/desired-outcome/prompt/checklist copy differences throughout: consistent with two different dates of the same underlying Huddle content, not a code path issue.

### (c) Confirmed intentional, kept as-is

- The extended font-stack (`"Segoe UI Variable", "Segoe UI", system-ui, …`) and `font-family: inherit` forcing on form controls/details/tables.
- "Desired outcome" no longer rendering bold.
- Both changes carry in-file comments recording they were deliberate, manager-directed presentation fixes made after the mock was produced — reverting them would be a regression, not a fix.

## 3. Exact logic changed

All changes are in `exportHuddleHtml.ts`:

1. `activityCard(activity, index, tier)` — dropped the `discussionWhilePracticing` parameter; `Context Required` now renders as `<p>{activity.requiredContext}</p>`; the second detail card is now `<section class="activity-detail-card activity-wiifm-card"><h3>Why This Matters</h3><p>{activity.whyThisMatters}</p></section>` (with the existing placeholder fallback for a null value).
2. Its two call sites in `createHuddleHtmlExport()` (featured and optional activity stacks) updated to match the new 3-argument signature.
3. `resourceHubToolCard(agent, isTopFive)` — new `isTopFive` parameter drives the `top-five-resource` card class and the `resource-tool-badge` markup; the only call site now passes `topFiveUsedAgents.includes(agent)`, reusing the array `createHuddleHtmlExport()` already builds.
4. Removed the now-unused `.activity-discuss-card` CSS rule and its stale comment from `HUDDLE_EXPORT_STYLE_FIXES`.

No changes to `htmlTemplate.ts`, `htmlSanitizer.ts`, `huddleGuideStyles.ts`, `huddleGuideAssets.ts`, `fontStack.ts`, the presentation types, the mapper, or any data file.

## 5. Second pass — agent links and the Resources panel (follow-up)

After reviewing the first pass, you flagged two more gaps against the reference screenshots: missing "Open agent" links next to agent names, and the Resources panel not matching the reference layout. Re-investigating those two specifically surfaced real code bugs, not just data differences:

**Access links were being suppressed everywhere.** `agent.showAccessLink` gates `agent.accessUrl` in both the activity tool-action rows and the resource cards. Traced this back to the raw `HuddleActivityAgents.json` / `HuddleTopicAgents.json` join tables: their `ShowAgentAccessLink` column is `0` for essentially every row relevant to this Huddle, even though `AccessUrl` and `AccessLinkLabel` are populated for the agent. Rather than have the export silently drop a working link because of that flag, both places now show the link whenever `agent.accessUrl` resolves to a valid URL — using only our own existing `accessUrl`/`accessLinkLabel` fields, nothing invented. **Flagging this rather than treating it as fully settled:** the `ShowAgentAccessLink` flag does vary (`0`/`1`) elsewhere in the data, so it may be meaningful in other Huddles even though it wasn't for this one — worth a data-layer look if links start appearing somewhere they shouldn't.

**The resource card's subtitle and "What it is" detail box had their fields swapped.** Checked the raw `HuddleAgents.json` directly: `WhatItIs` holds the short category ("Orchestrator", "Domain agent", "Agentic workspace", "Agent", "General agent") and `ShortDescription` holds the long paragraph. The code had these backwards — the long paragraph was showing as the subtitle under the agent's name, and the short category word was buried inside the "What it is" box. Swapped: subtitle now reads from `whatItIs`, the "What it is" box now reads from `shortDescription`. (I'd previously misread this as a legitimate Sept‑18-vs-Sept‑23 data difference; re-checking against the raw table this pass showed it's a straightforward field-mapping bug in the export code.)

**"Surfaced through" agents (ECIF Agent, Deal Agent, CX Vitals) weren't getting the secondary badge/subtitle treatment.** Our own `HuddleActivityAgents.json`/`HuddleTopicAgents.json` already encode this relationship consistently as a `DisplayLabel` of the form `"X, surfaced through Y"` (45 rows across those three agents, all "surfaced through Sales Agent"). The export was rendering that whole string as one name. Added a small parser for that exact pattern (used by our own data, not invented): when it matches, the card now shows the plain agent name in the heading, a "Surfaced through Y." subtitle, and — when Y is itself an official Top 5 agent, checked via the same artwork-matching already used for the primary Top 5 badge — a secondary "Surfaced through Top 5 Agent" badge, matching the reference's `is-surfaced` badge style that was already defined in CSS but unused.

**The Resources panel's summary text and count pill didn't reflect the Top 5 feature.** The pill went from "N AI tools · M resources" to "N AI tools · K Top 5 agents · M resources" (the `K` reuses the `topFiveUsedAgents` count already computed for the badge/band logic), and the panel's description now reads "Activity-mapped agents are shown in governed order, with official Top 5 agents and Sales Agent experiences identified where applicable." — describing the feature that's now actually implemented, in place of the old generic "Tools used across the Explore & Practice activities."

All of this is confined to `resourceHubToolCard()`, `activityToolActions()`, `agentBrandMark()` (given an optional label override so the surfaced-through card's logo `alt` text matches its shortened heading), two new small helpers (`isOfficialTopFiveAgentName`, `SURFACED_THROUGH_PATTERN`), and the Resources panel header line — still all in `exportHuddleHtml.ts` only. Re-verified against real `AE-PLAN` data with the same harness as before: `tsc -b --force` is clean, and the regenerated export now shows the Top 5 badge on Cowork/Scout/Sales Agent, the "Surfaced through Top 5 Agent" badge on ECIF Agent with a plain "ECIF Agent" heading, correct subtitle/detail placement for all five agent cards, working "Open …" links on 9 activity tool rows and 8 resource cards, and the "5 AI tools · 3 Top 5 agents · 14 resources" pill — matching the structure of your reference screenshots.
